# Local source-input workflow (never included in dist/)

Place authorized local material in `source-input/pyqs/<year>/` with `paper.pdf`, `final-key.pdf`, and `permission.json`. This directory is ignored by Git except this README; the static build only copies HTML, js, css, data and assets. Supplying a PDF is not permission to republish it.

permission.json should record year, paper code, session, original official paper/key URLs, rights holder, exact license/permission reference, grant scope (public website reproduction, question text, diagrams and adaptations), restrictions, reviewer and review date. Store documentary permission evidence locally alongside it. Do not invent a license, reviewer or signature.

A content maintainer must inspect the original files, verify completeness and final-key identity, resolve source rights, write original solutions and check every diagram. Do not set catalogue readiness from file presence alone. Publish only deliberately cleared assets. If you have files already, provide their local paths; no email is sent automatically and no access control is bypassed.
